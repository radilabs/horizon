# Documentation

`docs/` stores durable technical knowledge that future work and future agents need.

Write here when forgetting something could cause a future implementation choice to be wrong.

Use `docs/` for items such as:

- external API behavior and constraints
- normalized schemas
- caching and staleness rules
- credential/configuration storage behavior
- build, install, and debugging procedures
- known platform limitations

Do not use `docs/` for task execution progress or temporary findings. Those belong in the active phase task file.

Do not use `docs/` for durable architectural/product decisions. Those belong in `decisions/`.

Accepted phase snapshots live in `docs/handoffs/`.
